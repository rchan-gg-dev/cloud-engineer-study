Linux SSH / SCP Commands
========================

[SSH]

SSH
  ネットワーク経由で別のLinuxマシンを安全に操作する仕組み

標準ポート：
  TCP 22


[SSH Client / Server]

SSH Client
  SSH接続する側
  sshコマンドを使用

SSH Server
  SSH接続される側
  sshdが動作


[SSHサービス]

sudo systemctl start ssh
  SSHサーバーを起動

systemctl status ssh
  SSHサービスの状態を確認

sudo ss -tlnp | grep ':22'
  TCP 22番ポートがLISTENしているか確認


[SSH接続]

ssh <ユーザー>@<接続先>

例：
  ssh rchan@127.0.0.1

接続後：
  whoami
    接続ユーザーを確認

  hostname
    接続先ホスト名を確認

  pwd
    現在地を確認

exit
  SSH接続からログアウト


[初回SSH接続]

初めて接続するホストでは、
接続先のホスト鍵を信頼するか確認される

yesを選択すると代表的には：

  ~/.ssh/known_hosts

へ接続先の情報が保存される


[SCP]

scp
  SSHを利用してファイルを転送

基本形：

  scp <コピー元> <ユーザー>@<接続先>:<保存先>

例：
  scp ssh_test.txt rchan@127.0.0.1:/tmp/ssh_test.txt

実際のリモートサーバーでは：

  ローカルPC
    ↓ scp
  リモートサーバー
    ↓ sshで接続
  ls / catなどで転送結果を確認


[公開鍵認証]

パスワード認証：

  SSH接続
    ↓
  パスワード入力
    ↓
  ログイン


公開鍵認証：

  接続元
  秘密鍵
    ↓
  SSH認証
    ↓
  接続先
  公開鍵を登録
    ↓
  認証成功


[秘密鍵 / 公開鍵]

秘密鍵
  接続する側が保持
  他人に渡してはいけない

公開鍵
  接続される側へ登録してよい


[authorized_keys]

~/.ssh/authorized_keys
  SSHログインを許可する公開鍵を登録するファイル

覚え方：

authorized_keys
  → 誰をログインさせるか


[known_hosts]

~/.ssh/known_hosts
  過去に接続したSSHサーバーのホスト鍵を記録

覚え方：

known_hosts
  → 接続先が以前と同じ相手か確認


[秘密鍵指定]

ssh -i <秘密鍵> <ユーザー>@<接続先>

-i
  SSH認証に使用する秘密鍵を指定

例：
  ssh -i key.pem ec2-user@10.0.0.10


[AWS EC2との関連]

EC2へのSSH接続例：

  ssh -i key.pem ec2-user@<EC2のIP>

接続元：
  秘密鍵を保持

EC2側：
  対応する公開鍵が登録されている

秘密鍵（pem等）は第三者へ渡さない


[SSH鍵の権限]

秘密鍵は他ユーザーから読めないよう
厳しい権限にする必要がある

代表例：
  600 = rw-------

SSHでは秘密鍵の権限が緩すぎると
安全上の理由で使用を拒否される場合がある


[重要ポイント]

SSH
  → リモートLinuxへログイン

TCP 22
  → SSHの標準ポート

SCP
  → SSHを利用したファイル転送

秘密鍵
  → 接続する側
  → 他人へ渡さない

公開鍵
  → 接続先へ登録可能

authorized_keys
  → ログインを許可する公開鍵

known_hosts
  → 接続したサーバーの身元確認用情報
