■ NAT Gateway

Private EC2にはPublic IPv4を付与していない。

NAT Gateway作成前:

curl -4 -I --connect-timeout 5 https://aws.amazon.com

→ Timeout


Private Route Table:

0.0.0.0/0
→ NAT Gateway

を追加後:

curl -4 -I --connect-timeout 5 https://aws.amazon.com

→ HTTP/2 200


Private EC2はPublic IPv4なしでも、
NAT Gateway経由で外向きインターネット通信が可能。

確認後、
NAT Gateway削除
Elastic IP解放

■ 障害試験

Private EC2 Aで実施:

sudo systemctl stop httpd


結果:

最初は一時的に
502 Bad Gateway

その後Health Check失敗により、

EC2 A → Unhealthy
EC2 B → Healthy

となった。


ALBはUnhealthyなAを転送先から外し、
BのみでWebサービスを継続した。


■ 復旧試験

Private EC2 A:

sudo systemctl start httpd

systemctl is-active httpd


Health Checkが成功すると、

EC2 A → Healthy
EC2 B → Healthy

へ復旧。

ブラウザからA/B両方が
再び表示されることを確認。


■ 学んだこと

ALBは異常なEC2そのものを修復するわけではない。

Health Checkにより
異常なターゲットを切り離し、
復旧後に再び転送対象へ戻す。

障害発生から切り離しまでには
Health Checkの判定時間があるため、
一時的に502が発生する場合がある。
